# NOHRD Legacy GFIT App

App-only legacy firmware experiment for existing D52Q/GFIT products.

This project is intentionally separate from `nohrd_bike` and `d52q_gfit_bridge`.
It explores the conservative update path for field devices that cannot be opened
for SWD/J-Link access:

- keep the existing Legacy Secure DFU bootloader
- keep the existing ANT/BLE SoftDevice, most likely an S332-family build
- OTA-update only the application
- preserve ANT/ANT+ functionality
- replace or simplify the GFIT BLE behavior in the application layer

The goal is not Zephyr/NCS. Mixing Zephyr BLE with an old ANT/BLE SoftDevice is
not practical because both stacks need ownership of the radio scheduler.

## Intended Architecture

```text
Existing MBR
Existing ANT/BLE SoftDevice
Existing Legacy Secure DFU bootloader
New application
  - GFIT-like UART protocol toward Atmega
  - ANT/ANT+ through sd_ant_* API
  - BLE through sd_ble_* API
  - no forced BLE bonding/pairing unless explicitly required
```

## BLE Strategy

The main compatibility problem reported in the field is old GFIT BLE behavior:
pairing/bonding friction, stale bonds, unreliable reconnects, and mobile devices
needing manual unpair/re-pair cycles.

The first application-only attempt should keep BLE deliberately simple:

- advertise as connectable, not bond-required
- expose fitness services without requiring pairing
- avoid whitelist-only advertising
- avoid storing bonds unless the profile absolutely needs it
- clear or ignore stale peer data if the old app stored it
- use robust connection parameters for modern phones/tablets

## ANT Strategy

ANT must remain handled by the existing SoftDevice through the classic
`sd_ant_*` API. The application should preserve whichever ANT+ profiles the
current GFIT application exposes.

## Files

- `src/main.c`: application skeleton and init order
- `src/gfit_uart.*`: GFIT UART frame parser/encoder shell
- `src/ble_legacy.*`: intended BLE behavior using `sd_ble_*`
- `src/ant_legacy.*`: intended ANT behavior using `sd_ant_*`
- `include/nohrd_legacy_config.h`: product and protocol constants
- `tools/package_legacy_dfu.ps1`: placeholder package command

## Test Packages

The `build/` directory may contain acceptance-test packages. These are not
customer firmware and are not expected to boot on the old GFIT module.

- `D52QGF-ap_4.04.01_plain_zephyr_acceptance_test.zip`
  - Generated by `nrfutil nrf5sdk-tools pkg generate`.
  - Uses the Zephyr bridge binary as a raw application payload.
  - Standard generated SHA256 hash and CRC boot validation.
- `D52QGF-ap_4.04.01_plain_zephyr_no_validation_test.zip`
  - Same payload, but generated with `--app-boot-validation NO_VALIDATION`.
- `D52QGF-ap_4.04.01_plain_renamed_acceptance_test.zip`
  - Same no-validation payload, but renamed to the Garmin-style outer structure:
    `encrypted_nrf52832_xxaa.bin`, `encrypted_nrf52832_xxaa.dat`,
    `manifest.json`.
- `D52QGF-ap_4.04.01_old_init_plain_zephyr_test.zip`
  - Uses the Garmin 4.04 init-packet structure instead of the newer
    `nrfutil pkg generate` structure.
  - Patched values:
    - `fw_version: 15`
    - `app_size: 124404`
  - `nrfutil display` reports the same legacy style as the Garmin package:
    empty ECDSA signature, `hash_type: NONE`, no boot validation.

Warning: If a test package is accepted by the bootloader, it may replace the
working GFIT application with an image that cannot start or cannot re-enter DFU.
Use only on a module that can be recovered or on a test unit where loss is
acceptable.
